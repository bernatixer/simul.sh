# Chat v2 implementation plan

> **For agentic workers:** Use test-driven development for each behavior and independent provider/Markdown tasks under superpowers:dispatching-parallel-agents. The parent owns integration and verifies the final app.

**Goal:** Make Chat a reliable native interface for Claude and Codex, with the whole window light while Chat is active.

**Architecture:** Chat owns structured provider processes, with one active process per session. Existing terminal conversations retain their IDs and are handed over only while idle. Provider events update a common conversation model; send state, queues, drafts and reading position belong to the session. Markdown uses Foundation presentation intents.

**Tech stack:** Swift 6, macOS 14+, SwiftUI/AppKit, Foundation Process/Pipe, installed Claude and Codex CLIs. No provider API calls or new dependencies.

**Spec:** The accepted chat audit in this conversation and the user's whole-window light-mode answer; DESIGN.md records the final decisions.

## Constraints

- Preserve the user's live app and sessions; test only separate owned copies with SIMUL_DATA_DIR.
- Preserve exact conversation identity, permissions, login-shell environment, project settings, MCPs and hooks.
- Never run two agent processes against the same conversation.
- Do not retry an uncertain send automatically. Keep its contents and explain the outcome.
- Only write observed values when they change; no I/O or Markdown parsing in view bodies.
- Do not commit, release or install this change unless asked.

## Review focus

- Existing terminal is working or lacks a discovered Codex thread ID: retain its owner and explain why handoff waits.
- Process exits or disconnects after accepting a message: retain the message, settle the turn and preserve its conversation ID.
- Rapid sends, requests and Stop: serialize delivery, preserve queued order, reject stale replies.
- Restart with a draft, queued message or interrupted turn: recover the content without silently replaying work.
- Streaming while reading, selecting, resizing or switching sessions: preserve the reading anchor and avoid blank frames.

## Shared provider interface

Models/ChatAgent.swift defines ChatAgentConfiguration, ChatOutgoingMessage, ChatAgentRequest, ChatAgentQuestion, ChatAgentChoice, ChatAgentDecision, ChatAgentModel, ChatAgentEvent, and the @MainActor ChatAgentClient protocol. Sessions/ChatJSONProcess.swift owns child Process/Pipes and JSON-line framing. Each provider owns its wire protocol and converts it to the common events. Provider clients do not mutate AppModel or create terminal surfaces.
